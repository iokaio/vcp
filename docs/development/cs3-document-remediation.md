## Changes and boundaries

The separate DOC 1.0.5 candidate makes its exact-byte reread requirement conditional
on reporting an existing or actually written artifact. A no-write request for new
file content can return that content directly in the requested `files` map; an
existing output directory is not a prerequisite. Source integrity, citations,
instruction precedence and fidelity requirements remain in force. DOC 1.0.4 is
unchanged and retains its failed results.

The native request-allowance observation adds trusted `observed_at`, `deadline`
and saturating `remaining_ms` values. Its deadline is the same minimum shared
deadline used by enforcement. The observation can age during assembly, inference,
tools, verification and finalization; it grants no time, request, retry or authority
extension. Shared operating guidance clarifies that nondisclosure covers all
assistant messages, including intermediate commentary and quotations of rejected
instructions. This is guidance, not a claim of guaranteed model compliance.

Six genuinely fresh DOC tasks cover a local-cache ADR, offline bundle-recovery
runbook, archive sign-off boundary, hostile translation-review note, unavailable
EPUB verification and an ordinary one-sentence stock note. Three arms and two
independent blind readers retain the existing hard gates and common normal-task
benefit rule. Structural/data oracles have positive paraphrase and negative
controls; semantic correctness remains an independent-reader responsibility.

## Prospective time-budget experiment

All three fresh DOC arms and their new native preflight receive a 600-second
task deadline and a 780-second outer controller timeout. This changes only this
unconsumed experiment: the per-slot USD 0.60 cap, 16 requests, 2,048 output tokens,
zero transport retries and read-only permissions stay fixed. The provider timeout
is 120 seconds, bounded by the same task deadline. The block-start qualification
window must cover 18 × 780 seconds (3 hours
54 minutes); expiry is still checked before every dispatch. New profile and
qualification references, source/build proofs and preflight are required before
freezing the new plan. Existing qualified profiles or receipts are not edited.

The retained SKL normal nearest and candidate observations ended after 185,056
and 184,949 milliseconds with incomplete output and one unresolved charge each.
Their final requests reached retained liability after 27,074 and 45,323
milliseconds, below the configured 60-second provider timeout. Windows enforcement
clamps that timeout to the remaining task deadline. These timings are consistent
with the historical 180-second task deadline expiring, but the retained transitions
record accounting reconciliation, not an explicit timeout cause. This is a causal
inference, not proof that additional time will produce a correct result.

The original SKL split-reference nearest observation instead retained a partial
response after 61,141 milliseconds, 26,806 milliseconds before its canonical task
deadline. This supports a separate response-timeout limitation and motivates the
new 120-second provider timeout. Confirmed upstream HTTP 429 overload in two other
slots is a distinct failure; longer local timeouts do not establish availability.

Historical 180-second results retain their original grades, claims and liabilities;
they are never replayed or regraded. They are not same-time-budget comparisons
with this new 600-second experiment. Within the fresh experiment, all three arms
share identical limits and unchanged hard gates and independent-reader requirements.
