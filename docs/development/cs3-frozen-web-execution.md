# CS-3 frozen WEB execution

The successor executable adapter preserves the immutable WEB v1 manifest
(`dbe34a441187381f0e5d3f587ea72b0ac15e096ca9d90f99a065ef8e51d84ee8`)
and its historical `not_run` preparation fields. Results belong to a separate
`cs3-webapp-execution/1` receipt, never a rewritten historical manifest.

`FrozenWebResources.cs` embeds the exact five HTML/JavaScript byte sequences for
the form, polling and hostile redirect cases. `webapp-execution.cjs` independently
joins each compiled byte sequence to the frozen manifest. The host accepts no
project path, script, command, URL or runtime option from a page or model.

The existing zero-capability AppContainer, hidden WebView2, owned jobs, exact
runtime inventory, process census and disposable-profile cleanup remain the
execution boundary. After the synthetic qualification sequence, the fixed WEB
sequence uses eight exact supervisor-owned server responses. The supervisor
requires the exact routes, status, content type, length and body bytes before
acknowledging a host request. `/ready` must return 204; `/poll` returns the frozen
503 then the frozen Alpha/Beta response. A separately held idle connection stays
open through completion, independently checked before server shutdown.

The browser dispatches one Tab pair and one empty Enter pair, then literal Ada
and one Enter pair for the form. Polling Retry and hostile Continue each receive
one real pointer press/release at the read-only, bounded control rectangle.
The hidden message-only parent stays invisible; its 800x600 child renderer is
enabled after the form oracle so Chromium can perform pointer hit testing.
Bounded read-only observations wait for those already
dispatched actions; no input is retried or replaced with a synthetic DOM event.
The page bytes receive no instrumentation. DOM snapshots cannot edit the page.
The accessibility snapshot is bounded to 64 KiB and projected to named roles.
The supervisor separately reconstructs and grades all eight ordered documents.
Hostile evidence includes only URL/origin, never page text or private attributes.

The non-browser adapter separately exercises the occupied requested port,
the unavailable-browser condition and the near-miss unit oracle. The occupied
listener is a harness-owned actor representing the preserved user service; a
second bind must fail with `EADDRINUSE`, and the actor must still return
`KEEP_RUNNING`. If the requested port was occupied before the harness starts,
the case reports unavailable without probing or adopting that real listener.
The missing-browser case truthfully records browser checks as not run. The
original near-miss implementation fails the non-ASCII requirement; detecting
that defect is an oracle result, not a claim that the frozen source was fixed.

Eight Node execution/oracle tests and 26 independent native WEB evidence assertions
pass. The original normalization source fails its non-ASCII oracle as expected;
the occupied-port and missing-browser oracles pass their explicit conditions.
