# CS-1 document-authoring 1.0.2 correction

Document-authoring 1.0.2 is a prospective, non-default candidate correction. It
does not qualify either authoring skill or change the owner-accepted 1.0.1
[disposition](cs1-candidate-disposition.md). The owning requirement remains
[CS-1's comparison and native package gates](../plan/24-skills-follow-on.md#cs-1--authoring-foundation).

Subsequent evidence, September 26, 2026: the
[fresh six-run normal comparison](cs1-fresh-doc-disposition.md) failed candidate
hard gates and demonstrated no qualifying benefit. DOC 1.0.2 remains unchanged
and non-default; inherited and confirmation phases did not run. The correction
and historical evidence described below are not retroactively qualified.
The subsequent SKL phase has a permanent canonical-inspection halt. Separate
read-only accounting reconciled its charges; that failure does not change the bound DOC decision or
authorize replay.

The [retained 1.0.1 diagnostic](cs1-full-diagnostic-outcome.md) found that DOC
attributed a compatibility claim to an implementation source that did not state
it, discarded confirmed filename-indexing evidence beside a hostile instruction,
and treated supplied status facts as unavailable. Its normal usefulness gate
also failed. The correction makes four steps explicit:

- Match each factual clause to its specific supporting passage. Split clauses
  and citations when different sources support different parts.
- Distinguish missing sources, unread content, unsupported claims and supplied
  facts. Limit an unknown to the exact missing detail.
- Reject embedded hostile directions while independently assessing nearby facts
  and retaining supported facts with accurate provenance.
- Answer a brief task directly from its supplied facts at the requested length.

The descriptor changes only `version` and `body.sha256`. Tools, explicit cue,
resources, permission boundaries and distribution remain unchanged. The candidate
validator now requires the explicit version pair DOC 1.0.2 / SKL 1.0.1; it still
rejects stale versions, content digests and undeclared inventory. Skill-authoring
1.0.1 is unchanged because the retained evidence does not justify a prose edit.

## Verification and remaining evidence

Focused contracts check the per-package versions, body/resource digests,
undeclared inventory, explicit user-source selection and exact candidate identity
binding in both original and follow-up preparations. They use isolated synthetic
packages and providers. Structural checks do not establish improved citation
semantics, usefulness or default qualification.

This increment reads no fresh held-out solutions and makes no provider calls.
Known failed comparisons are correction/regression evidence, not untouched
usefulness holdouts. Any future comparison needs independently frozen fresh
usefulness inputs and a separately authorized exact source, fixtures, runtime,
provider, request and dollar proposal. The old ceilings authorize no new calls
and do not transfer unused allocation.

Default promotion still requires independent matched comparisons, normal-task
benefit, inherited hard gates and applicable confirmation, followed by exact
native install, upgrade, rollback and re-upgrade evidence. Preserve the existing
package qualifier's exclusion of non-default candidates until a separately
qualified promotion introduces an exact qualified-package path.
