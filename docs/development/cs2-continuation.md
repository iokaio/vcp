## Continuation contract

The original campaign implementation remains frozen. Three companion modules
provide the new boundary:

- `developer-reconcile.cjs` authenticates the original halted evidence without
  writing to it or treating the halt as permission to resume.
- `developer-continuation.cjs` prepares a new private directory and fresh stores,
  binds its source, fixtures, candidates, runtime, provider qualification and
  exact budget in a hashed plan, and uses a separate one-shot repository claim.
  It schedules only the original cohort minus the eight dispatched IDs.
- `developer-continuation-review.cjs` composes each original eighteen-run block
  from authenticated historical and fresh evidence. Grading, anonymous packets,
  two independent blind reviews and decisions are written only to the new
  continuation. The original failed run cannot become an executable success.

The model remains `openai/gpt-5.6-luna` through OpenRouter's
`amazon-bedrock/us-east-1` endpoint. Every request retains the existing 2,048
output-token limit, canonical tool ceiling, scoped fixture workspace and pinned
data-only checker. Functional execution remains in the pinned AppContainer
grader. Payloads remain the synthetic fixtures, selected skill instructions and
generated outputs. No unrelated projects or credentials enter those payloads.

The provider qualification is reused only while current and long enough to
cover the next block's worst-case runtime. Its historical expiry is never
extended. Changed identities, unknown charges, authority failures or interruption
permanently halt the continuation. Qualification still requires the original
benefit and preservation gates; completing dispatch does not promote a skill.
