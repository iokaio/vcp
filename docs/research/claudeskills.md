# Claude skills: lessons and a VCP follow-on plan

Status: retained research. The owner authorized the [formal skills follow-on](../plan/24-skills-follow-on.md) under [ADR-068](../adr/068-skills-follow-on-before-other-hosts.md) on September 24, 2026. No skill, dependency, tool, activation rule or runtime behavior is added by this document.

Reviewed September 24, 2026 against VCP `a9a11fd2` and Anthropic skills revision `33375500bcea98d610eb30ce10ac4e59b89c390d`. The [requested upstream catalog](https://github.com/anthropics/skills/tree/main/skills) contained **19 skill directories** at the [pinned revision](https://github.com/anthropics/skills/tree/33375500bcea98d610eb30ce10ac4e59b89c390d/skills). This analysis reads each directory's `SKILL.md` and the repository README. It does not certify every referenced script, dependency, sample, SDK claim or subdocument; upstream workflows were not installed or executed.

## Recommendation

Under the revised sequence, with P10-04 explicitly deferred, add **six original developer-workflow skills** to VCP's default catalog: `document-authoring`, `frontend-design`, `webapp-testing`, `mcp-development`, `skill-authoring`, and `llm-integration`. Then qualify **two bounded document/data skills**, `pdf-workflows` and `spreadsheet-workflows`, for default distribution. These names are proposals, not existing package IDs.

Fold project communications into document authoring and user-owned design tokens into frontend design. Leave full Word/PowerPoint editing, standalone creative graphics, animation, themed artifact assembly, provider-specific training and standalone reflection nudges for later consideration. Do not reproduce Anthropic branding or make Anthropic's API the default for unrelated projects.

“Out of the box” means the original descriptor and guidance ship in the native VCP skill catalog and are discoverable through existing controls. It does **not** mean automatic activation, bundled third-party applications, installed browsers, network permission or unattended publishing. A capability is advertised as executable only for the toolchain and environment actually qualified. Basic authoring guidance can work without an executable adapter; missing conversion/browser/recalculation tools must produce an explicit unavailable/not-run result.

The original whole-P10 ordering is superseded by ADR-068. CS-0 through CS-6 now have formal owners in the separate skills plan; the original 68 architecture IDs and P10-04 acceptance remain unchanged. This neither reopens completed P7-02 nor inserts new gates into that ledger. The owner subsequently authorized continuation through CS-7 as an optional-pack demand review; no optional pack is selected.

## What the upstream collection teaches

The collection is broader than a coding skill catalog. It combines developer workflows, documentation, Office/PDF production, visual design, communication and Claude-specific reference material. The useful pattern is a recognizable user task paired with workflow guidance, selectively loaded references, tangible output and a way to check it. A skill can be more valuable when it says what constitutes a usable result than when it merely lists libraries.

Three lessons fit VCP particularly well:

1. **Keep guidance task-specific.** Separate authoring a document, building an MCP server and testing a web application from general language advice. Reuse existing language/testing skills instead of duplicating their contracts.
2. **Check the delivered artifact.** Validate document structure, formulas, links, rendered layout and actual browser behavior as applicable. Successfully running a generator does not establish that the output works or is readable.
3. **Compare the skill with a baseline.** Use held-out tasks, negative activation examples, independent output checks and measured user benefit. A larger skill body or a more aggressive trigger is not evidence of improvement.

Several upstream choices should not transfer. Claude-specific tool names, artifact presentation, browser/reviewer servers, direct SDK defaults, automatic package installation and unconstrained parallel evaluation are host assumptions. VCP already has canonical effects, explicit process profiles, root budgets, authority checks and recoverable artifacts. Skills must use those boundaries rather than introduce another execution loop.

The [upstream README](https://github.com/anthropics/skills/blob/33375500bcea98d610eb30ce10ac4e59b89c390d/README.md) distinguishes generally Apache-licensed examples from the source-available `docx`, `pdf`, `pptx` and `xlsx` implementations. Our decision is stricter than selecting a license: **copy no upstream code, skill prose, templates, fonts, images, evaluator scripts or sample tests**. Write original VCP requirements and synthetic fixtures from the observed user workflows and public format/protocol specifications. Keep the pinned research references; independently review any future library's license and notices. This analysis is not a per-file license clearance.

## Existing VCP foundation and missing capabilities

The [21-family catalog](../development/p7-builtin-skills.md) already covers architecture, review/debug, testing, Git, language ecosystems, data, infrastructure, optimization and memory hygiene. It has versioned descriptors, source/body hashes, integrity checks, explicit activation and packaged sidecar assets. The [catalog](../../src/skills/builtin/catalog.json) and [coverage records](../../src/skills/builtin/coverage.json) distinguish supplied guidance from observed qualification. Extend those records rather than add an Anthropic-compatible loader or competing skill registry.

| Existing boundary | Reuse | Missing work before the recommendation is fully supported |
|---|---|---|
| JS/TS, testing, review/debug | Project manifests, declared commands, meaningful regressions, current-source evidence | Browser profiles, owned local server lifecycle, target-origin policy and responsive/accessibility fixtures |
| Architecture and data | Source-grounded analysis, schema/provenance and exact numeric semantics | Document audience/structure checks; spreadsheet formulas, stale cached values and workbook preservation |
| P7-01/02 skill discovery and packaging | Explicit activation, precedence, versioned integrity and not-run diagnostics | New original packages, overlap/negative-selection tests, metadata/resource inventory and package upgrade tests |
| P7-03 governed MCP | Tool identity, scoped credentials, bounded content and cancellation | Server-development guidance and synthetic server conformance/usability fixtures; no automatic server registration |
| P2 process/tools and capture | Authorized paths, explicit executable profiles, intent/receipt, process ownership and bounded outputs | Separately approved converter/browser/recalculation profiles; safe previews and output validation |
| P4 inspectors and versioned edits | Reviewable artifacts and preservation of human changes | Any richer binary-document or visual preview integration must be explicitly designed; text edit receipts do not implement Office editing |

A key limit is visible in [`Content`](../../src/crates/vcp-context/src/manifest.rs#L61-L75) and the [request encoder](../../src/crates/vcp-models/src/request.rs#L276-L312): the current coding context exposes text and tool calls/results, not a general image-input part. Therefore “render and visually inspect” cannot silently become a model-vision capability. Initial checks can use deterministic DOM/layout measurements and user-visible previews. If automated model visual review is selected later, first define governed image capture, model/endpoint capability negotiation, size/token/cost bounds, retention and actual adapter qualification. No skill may claim to have seen pixels it only generated.

## Original implementation contracts for the default additions

### Document authoring

Create an original workflow for purpose, reader, source material, outline, drafting and review. Use a bounded clarification only when missing information changes the result. Preserve source citations and distinguish proposals from accepted decisions. Reuse the repository's templates and voice. For project updates, include actual outcome, evidence, unresolved items and next action; do not invent organizational facts.

Start with Markdown and existing project-native text formats. Validate local links/headings, cross-references and factual claims against authorized sources; keep privacy-sensitive source text out of unrelated outputs. Tests should include conflicting/stale source documents, missing evidence, hostile embedded instructions, an existing ADR that must be preserved, and a short update that should not become a lengthy process. A reader review is advice, not a second authority or permission to contact others.

### Frontend design and web application testing

Keep distinct skills: one designs/builds an interface; the other exercises it. Frontend guidance should reuse the selected framework, components and user-owned tokens, cover keyboard navigation, focus, contrast, responsive sizes, loading/empty/error states and reduced motion, and preserve unrelated work. Test against existing conventions as well as a new-project brief; visual novelty is not the sole success criterion.

Web testing must select an explicitly configured browser/test runner and permitted local target, start only an owned server if required, wait for bounded application-specific readiness (not unconditional global network-idle), exercise actual interactions, retain relevant results and stop owned processes on pause, cancellation or owner loss. Browser requests, remote assets, persistent profiles, downloads and uploads need explicit scope; loopback access must not imply access to every local service. Do not use a user's signed-in browser profile. Tests cover startup failure, occupied port, long-polling applications, timeout, preservation of an existing user-owned server, redirects outside the allowed origin, secrets in page content, failing keyboard interaction, changed source after a pass and cleanup after interruption. Install browser binaries only through a separately authorized provisioning step.

### MCP development

Guide construction of a server for the user's requested service and repository stack. Learn from upstream's schema/error/pagination emphasis, but independently design bounded contracts, actionable diagnostics, explicit side effects and credential separation. Treat MCP annotations as descriptive hints, not permission. Pin documentation/SDK versions used for generated code and keep protocol logs separate from stdio transport.

Qualification uses synthetic local services and independent client assertions: malformed/numeric inputs, pagination, tool/resource/prompt identity, cancellations, authentication expiry, denied effects, oversized output and schema drift. Include realistic task success, not just server startup. Connecting the server to VCP, granting access or publishing it remains a separate explicit configuration/action.

### Skill authoring

Draft a VCP-native package from a stated task, scope, expected outputs and exclusions. Include a descriptor, original body, permitted reference resources, provenance and fixtures; compute exact hashes through VCP tooling. Reuse canonical activation instead of inferring permission from a name or keyword. The first deliverable is a reviewable candidate, not self-installation or self-activation.

Compare new candidates against no-skill and overlapping existing skills; compare revisions against the old version. Include near-miss tasks, malicious instructions in reference material, missing tools, changed resource hashes and excessive activation. Reuse the normal task/child budget and pause model for any evaluated runs. Prefer bounded scheduled runs to spawning every case at once. Held-out evaluation prompts and independent checks must not be rewritten to accommodate a candidate's failures. Use this workflow to develop subsequent proposed skills without making its own success depend on them.

### Provider-neutral LLM integration

Help users build or review applications using the provider/SDK they selected. Separate external application code from changes to VCP's own inference implementation. Inspect installed versions and official primary documentation; keep provider-specific details in optional reference sections loaded only for that task. Record documentation dates and unknowns; do not ship a changing price/model table as timeless truth.

Cover streaming/cancellation, tool-result matching, structured outputs, context bounds, rate limits, explicit retry policy, credentials and usage/cost observations. Include the [prompt-audit lessons](../claude-audit.md): source facts and measured benefits are different, historical calls can constrain schema changes, and caching requires byte-level and endpoint/accounting evidence. Tests include a non-Anthropic project, a mixed-provider app, unavailable documentation, malformed outputs and a requested migration with immutable historical evidence. Live provider tests require an established budget; deterministic mocks cannot qualify production compatibility.

### PDF and spreadsheet workflows

These should become default skills only after a narrow local executable path is qualified. Choose dependencies from independent requirements and measurements; this research does not select a PDF engine, office suite, Python library or spreadsheet evaluator.

PDF scope starts with page-bounded extraction from supported text PDFs and generation of new documents from controlled source material. Preserve originals; report encrypted, scanned, malformed, oversized and unsupported documents distinctly. Qualify page provenance, Unicode/fonts, tables and known layout fixtures. Defer OCR, signatures, arbitrary forms, reliable redaction and editing of complex originals until separately tested. Blacking out visible text is not secure redaction.

Spreadsheet scope starts with bounded `.xlsx` reading and creation/modification of a declared feature subset, with CSV interchange where semantics permit. Preserve cell types, units, date systems, formulas and sheet/range provenance; do not label cached formula values as freshly recalculated. Qualify recalculation through a selected engine, expected-value and intended-range/reference oracles, round-trip loss detection and errors on unsupported features. Error-free recalculation alone does not establish mathematical correctness. Default-deny macros and external link refresh; check formula injection when exporting untrusted text to CSV. Defer `.xlsm`, pivots, data connections and complex chart fidelity until their preservation/security matrices pass.

Every converter writes to a new owned output and validates it before replacing an existing artifact under expected-source checks. Bound archive expansion, entry counts, nesting, input/output size, runtime and temporary storage; reject path traversal and unsafe XML external-entity resolution. Treat embedded links/instructions and converter diagnostics as untrusted. Missing dependencies produce setup guidance, not downloads or unsupported success claims. Native Windows, spaces/Unicode/long paths, locked files, pause/kill and original-file preservation are required tests.

## Acceptance, evaluation and maintenance

For each candidate, predeclare normal, boundary, hostile-input, missing-tool and near-miss tasks. Compare with no skill and with the nearest existing skill; use the old version when revising a package. Record exact source, skill/resource hashes, model/provider identity, toolchain, fixture and output digests. Evaluate correctness, preservation, user interventions, unnecessary tool calls, latency, total root/child cost and omitted/not-run checks. Do not judge a skill solely by token reduction, prettier screenshots or an evaluator model's preference. Independent structural oracles and blind human judgments serve different purposes.

Run cheap deterministic tests first. Any live model campaign needs its own authorized budget and retained failed/unknown charges. Helpers inherit the same root budget and do not automatically receive process authority. Do not weaken frozen fixtures or claims because a toolchain is unavailable. Negative or uncertain benefit can end a candidate as deferred/rejected rather than as another permanent default.

Default distribution must update original skill descriptors, catalog/resource hashes, coverage evidence, notices and standalone native package tests. The VS Code extension continues to use the engine's selected catalog; do not create a divergent editor-only catalog. Resources need bounded activation/context costs and refresh rules. Existing sources and user skills keep their documented precedence; old receipts and evidence retain their original identities after upgrade.

Revisit API/protocol/format references when a supported dependency changes. Recheck this upstream inventory by revision before implementation, without automatically importing newly added skills. Ship only explicitly supported features and environments. This document supplies research and a route to evidence. ADR-068 authorizes the sequencing revision; the owner subsequently requested delivery through CS-7, one PR per skill. Neither document supplies runtime qualification, release authorization or paid-evaluation permission.
