# P6-02 canonical routing shadow

This increment connects the bounded decision codecs to actual admitted coding
routes. It does not complete P6 or qualify a shipping evaluator. Production native
Decisions remains unavailable without a qualified finite charge bound; controlled
fixtures cannot enable production transport. No paid provider calls are part of
this qualification.

## Implemented boundary

The canonical worker retains the actual main attempt, routing baseline and
verified source context. A caller-owned asynchronous observer checks current
source, destination, permissions, qualification and credentials, then captures and
reserves one separate helper attempt. There is no automatic retry or fallback.
The baseline remains unchanged for advice, abstention and failure.

The native Decisions and conventional Chat requests use closed endpoint and body
contracts. Both share bounded TLS transport with task/owner/credential fences.
Known cost survives invalid advice and late transport failure. Missing trustworthy
cost retains unknown liability; reopening never resends a shadow request. CLI
drivers keep control commands responsive and join cancellation before owner close.

The shared context prerequisite reuses the same full capture validation for both
initial verification and borrowed revalidation; retaining an `Arc` does not reduce
source checks. MCP transport keeps its existing credential boundary through a
closed dispatch enum.

## Qualification scope

The reproducible runner is
`scripts/evals/decision-shadow-qualification.ps1`. Native controlled-peer cases
cover both stores, both evaluator body formats, actual main-attempt linkage,
unchanged baseline, known/unknown charges, lost replies, late framing failure,
cancellation/owner loss/reopen, and zero-I/O rejection. Source, credential and pause
changes are injected after TLS and before HTTP transmission. Unit tests cover
credential filtering, admission bounds and borrowed source revalidation.
