# Adaptive allocation offline qualification

Work item: EE-03c. These deterministic local fixtures exercise the existing canonical coding/provider path. They use synthetic catalogs, prices and reported usage; they do not qualify a real endpoint, measure tokenizer accuracy or compare model quality. Their explicitly finite compatibility cases retain finite spending and deadline checks; normal collection follows the approved unbounded execution policy. Operational request and provider-capacity limits remain enforced. The implementation and acceptance contract are in the [execution architecture review](../architecture/execution-architecture-review.md#61-adaptive-request-and-response-token-limits).

The new routed and large-patch fixtures join every transmitted request's exact bytes and SHA-256 to one canonical attempt and retained request artifact. They assert serialized `max_output_tokens`, quoted output bound, manifest envelope and allocation equality, reservation identity/amount and settled versus unresolved disposition. Routed requests additionally validate their persisted decision, selected model/endpoint, provider selection and candidate-specific output bound. No fixture substitutes an oversized limit for a hard provider bound.

The large patch uses a catalog declared before admission with 128,000 context capacity, 120,000 input capacity and the same 8000 output maximum throughout. This gives the next request room for the complete edited source under the fixture's conservative byte estimator; the test does not change metadata during execution to bypass a failed admission. The reported 6000-token complete patch is scripted and does not establish the actual tokenizer count of its bytes.

## Verification and remaining acceptance

On October 4, 2026, the five allocator tests passed, the large-patch fixture passed on SQLite and Files (4.76 seconds), and both routed cases passed on both backends (40.86 seconds). The Rust fixture was formatted with edition 2021. Existing reopen, context and encoding rows identify prior verified regression coverage; they were not all rerun for this test-only increment.

The fixtures establish complete local edit application, safe incomplete output handling and exact admission agreement. They do not establish that adaptive limits improve a real model's edit quality, reduce cost or outperform a fixed allowance. The plan requires a small live probe assessing complete edits and result quality within real capacity, followed by full A/B and larger engagements; that integrated qualification remains open. This does not require a universal fixed-versus-adaptive campaign or a superiority claim. Retained diagnostic archives from the separate [fault qualification](execution-diagnostic-faults.md) remain available; these allocation tests use temporary canonical stores and are reproducible tests, not a newly retained archive package.
