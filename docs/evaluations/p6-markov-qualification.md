# P6-04 / M4 — Four-arm qualification and recorded rejection

The frozen manifest at `src/evals/markov/manifest.json` defines a synthetic,
project-separated and time-separated comparison for repeated-strategy suspicion.
Each project supplies only its own earlier training prefix. Algorithm parameters,
split membership, labels, severity, sample floors, tolerated errors, uncertainty
and rollback triggers are fixed before evaluation. Repeated fixture families are
not independent real projects and cannot qualify a shipping policy.

The runner executes the actual deterministic repeated-strategy predicate and
the frozen local statistical producer. It records actual Jev through OpenRouter
and the conventional OpenRouter comparator as **not run**, with zero requests
and no substitute results. No live evaluation cap is authorized by this work.

Classification output includes coverage, abstentions, precision, recall and
serious misses, including serious cases on which the producer abstained.
Wilson bounds describe synthetic proportions only. Local wall timing is measured;
CPU time, peak memory, provider latency and task-level benefit remain unavailable.
Transition probabilities and entropy suspicion are not stall probabilities, so
the runner does not invent a Brier or calibration score. Independent M3 forecast
error and interval coverage evaluation is also not run; arithmetic correctness
tests are insufficient predictive evidence.

The manifest includes identical observable histories with opposite synthetic
outcome labels. These demonstrate a limit of the available observations, not a
reason to claim a hidden-state model knows the cause. No HMM is promoted without
evidence of an identifiable, useful improvement.

Qualification remains disabled per purpose. Missing live outcome trials,
calibration, sample coverage or known liabilities reject the candidate. Routing,
review and policy proposals receive no qualification from a stall-only producer.
No qualified `CostEstimate` is installed; configured assumptions, conservative
first-request bounds, protected verification funds and atomic reservation
ceilings remain the baseline. Source pruning, policy/catalog drift, sparse or
numerically invalid evidence and serious misses are explicit rollback conditions.

Run `scripts/evals/markov-qualification.ps1` to reproduce the offline result.
The run manifest binds source content before/after, the frozen input, toolchain,
commands, logs and result hashes. A passing runner means the evaluation executed
successfully; it does not mean the candidate qualified.
