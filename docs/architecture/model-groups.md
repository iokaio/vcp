The tier observations and the cross-tier synthesis at the end are the parts that should drive routing decisions; the per-model entries are the evidence.

Method: four parallel web research passes (one per tier), roughly 40 searches and 60 page fetches per tier, covering vendor model cards, Artificial Analysis (AA), Vals AI / BenchLM, Scale MCP Atlas, Arena.ai, CodeRabbit, Entelligence, Quesma, METR, Hacker News, GitHub issues, and developer blogs.

Caveats that apply to every entry:

Pre- and post-overhaul numbers are not comparable; both are reported with dates. The "Coding index" column in the tables above predates the re-basing.

- **SWE-bench Verified** was withdrawn by OpenAI as contaminated in Feb 2026; treat any Verified score as a legacy third-party number.
- **Promotional prices.** GPT-5.6 Sol's $2/$10 is a 50% promo ending Sept 18 (list $4/$20). Solar Pro 4's $0.09/$0.36 is a 70% promo (list $0.30/$1.20). ### Frontier tier

#### Claude Fable 5.1

- **Identity:** Anthropic; released Sept 1, 2026 (with Mythos 5.1, Glasswing-only). API id `claude-fable-5-1`; OpenRouter `anthropic/claude-fable-5.1`. Closed weights. Positioned by Anthropic for "demanding reasoning and long-horizon agentic work, or when your evals on Opus 5 at higher effort still fall short"; Anthropic itself says "for most workloads, start with Opus 5."
- **Envelope:** 1M context (default and max, flat pricing), 128k max output. Adaptive thinking always on; effort `low/medium/high/xhigh/max`, default `high`; per-message effort change without cache invalidation (beta). Tools: yes; **forced tool use (`tool_choice: any/tool`) returns 400**, so use `strict: true` or structured outputs. Structured outputs: yes. Prompt caching: cache reads $0.25/M (0.025x base; 75% cut vs Fable 5), 512-token minimum. Thinking blocks are model-bound: editing earlier turns invalidates them (append-only history required; harnesses that inject/remove per-turn reminders break). Speed (AA, max effort): 67.3 tok/s, TTFT 244s (includes thinking); high/medium ~56 tok/s. $10/$50.
- **Benchmarks:**
  - SWE-bench Pro: 81.2% (BenchLM/CodingFleet aggregators, vendor-reported, Sept 2026); Anthropic's own launch post does not list it.
  - SWE-bench Verified: 95.0% (third-party leaderboards; not published by Anthropic).
  - Terminal-Bench 4.0: 55.8% (vendor) / 57.9% ±3.8 (CodingFleet, Sept 11) / 52% (AA v4.3, Sept 9).
  - Terminal-Bench 2.1: 91.4% (AA, Sept 1).
  - Terminal-Bench-Science 0.1: 52.6% (vendor).
  - LiveCodeBench: 90.52%, #1 (third-party, datasciencedojo).
  - DeepSWE v1.1: 67.4% (OpenAI's chart; Vellum notes this "makes the lead look bigger").
  - MCP Atlas: 87.2 ±2.05, #2 behind Muse Spark 1.1 (Scale, independent).
  - CursorBench 3.2: 73.4% max (vendor).
  - AA Coding Agent Index: 70 (pre-overhaul, #1, Sept 7) / 62 tied with Astra (v4.3, Sept 9).
  - AA Intelligence Index: 66 (Sept 1) -> 53 tied #1 (v4.3).
  - Arena WebDev: #2, 1758 (Sept 11).
- **Strengths (code):** Long-session agentic coding, multi-file refactors/migrations, debugging (Anthropic docs). Independent: "one prompt, no revisions" on a Go image codec and a portfolio site; 58% fewer output tokens and 36% faster than Opus 5 (thomas-wiegold.com). Every.to: "less than half the tokens of Opus 5 with comparable results" (via Vellum). Follows explicit tool instructions reliably; Millennium credited it with a years-old crash diagnosis (Anthropic).
- **Weaknesses / failure modes (code):** From Anthropic's own prompting guide (Sept 2026): (1) **parallel tool calling more variable**, often one call per turn where Fable 5 batched (extra turns/latency, not quality); (2) **whole-file rewrites for small edits** (more output tokens); (3) ends turn early / asks "Shall I apply this?" on async runs unless told it's autonomous; (4) scope creep: fixes nearby bugs and commits extra test files; (5) at `xhigh/max` drafts long deliverables in thinking then rewrites them (token/time burn); (6) at `low` answers from memory instead of searching; (7) safeguard false positives on "does this compile?" phrasing, obscure languages, base64 in tool output. AA: "slower than average and very verbose" (190M output tokens on its index run; $7.63/task v4.3). Cost is the main independent complaint.
- **Independent reviews:** Thomas Wiegold (Sept 4): outperformed Sol and Opus 5 in practical tests, but "high costs limit default usage". HN launch thread (49525378): mostly praise for more natural writing; many Opus 5 verbosity complaints redirected here. AA article (Sept 1): top of index but 20% costlier per task than Fable 5. mage-bench PR #23 (Sept 14): used as the stable baseline against Astra.
- **Best-fit VCP roles:** Planner and Investigator (long-horizon reasoning, best MCP Atlas and TB 2.1 numbers); escalation-target Editor for hard multi-file changes. Poor fit as cheap worker or Summarizer (cost, 244s TTFT at max). Run at `high`, add the batching/targeted-edit/autonomy prompt lines, keep history append-only.
- **Confidence:** High on envelope/vendor numbers; medium on real-world behavior (two weeks old; independent hands-on is thin but consistent).

- **Reliability failure modes differ by vendor:** Anthropic models under-batch tool calls and stop to ask permission (fixable by prompt); Astra corrupts/pads tool-call JSON and times out on OpenRouter (needs strict schemas + output caps); Sol reward-hacks and over-acts (needs sandboxing + a reviewer); Grok fabricates confidently; Fugu is slow and opaque.
- **Where each wins:** Fable 5.1: long-horizon planning, MCP/tool orchestration (87.2 MCP Atlas), hardest debugging. Opus 5: best default editor value inside Anthropic, top Arena text. - **Infrastructure risk:** Sept 3 correlated Azure outage took Fable 5.1, Opus 5, Sol/Astra and Grok down ~3h simultaneously (Requesty, Axios); OpenRouter fallback across vendors is the mitigation, but Fugu is unavailable in the EU and Sol's OpenRouter pricing is promotional.

#### Medium tier observations

- **Cost per solved task:** DeepSeek V4 Flash 0731 is the tier's floor: $0.06/$0.12 on OpenRouter, 98% cache discount, 227 tok/s first-party, and HN users report "struggling to spend more than $5/day" across 5-6 sessions. GLM 5.3 Flash is the best quality-per-dollar for agentic coding (DeepSWE 63.4, ~$0.02 per bug fix in a 12-hour OpenCode run) but pays for it in speed (~50-116 tok/s) and ~36% above-median verbosity. Qwen3.8 2.4T is the trap: $2/$6 looks mid-tier but reasoning burn makes it "second-most-expensive of 20 models per completed task" (codersera).
- **Agentic reliability ranking (evidence-weighted):** GLM 5.3 Flash > DeepSeek V4 Pro 0813 (with an external plan) ≈ Qwen3.8 27B (effort tuned to medium) > DeepSeek V4 Flash 0731 > Qwen3.8 Flash > Seed 2.1 Turbo ≈ Seed-2.0-Code > Nex-N2.5 Pro (unverified). V4 Pro's LiveBench Agentic result (last of 7 frontier peers) and Vals Terminal-Bench (54.7% vs vendor 87.9%) show vendor harness numbers are not transferable in this tier.
- **Shared failure modes:** Every reasoning model here defaults to a max-effort setting that causes overthinking/loops (Qwen 27B 22K tokens for an SVG circle; GLM thinking loops in Cline; DeepSeek Flash looping <10% into context). Set `reasoning_effort` to medium/low for Editor loops and Summarizer roles. DeepSeek Flash also hallucinates vision; strip image tools.
- **OpenRouter provider variance is a first-order variable:** for the same DeepSeek V4 Flash 0731 weights, GPQA swung 90%→75% and tool-call scores varied up to 20 points across hosts; GLM 5.3 Flash loop reports are NIM-specific and clean on Z.ai's API; speed spreads of 4-7x exist at the same price. Pin providers (Z.ai/Databricks/Fireworks for GLM; DeepSeek/PrimaLabs/Baseten for V4 Flash; Multiverse for Qwen 27B) and declare precision filters, but note "fp4 hosts land in the middle of the fp8 pack": filter on measured quality, not bits.

#### Low tier observations

- **Cost per task, not per token, reorders the tier.** Ling Flash (Novita $0.021/$0.063) and Mercury 2.5 ($0.04/$0.15) are cheapest per token, but Ling burns ~2.6x median tokens (AA) and Solar Pro 4 averaged 43k output tokens/task; Muse Glimmer is terse (59M tokens on AA's index vs Ling's 260M), so it can be cheaper per job despite $0.35/$1.50. Free tiers (Ling VL, Inkling Small, Nex Mini) carry 50 req/day caps and, for Inkling, training-on-prompts terms.
- **Structured output support is uneven on OpenRouter.** `response_format`/`structured_outputs` are exposed for Solar Pro 4, Mercury 2.5, Muse Glimmer, Nex Mini, Ling VL (paid only) and Ling Flash (DeepInfra only); **Inkling Small has none on any endpoint**, and the Ling/Nex free endpoints drop them. Pin the provider when schema adherence matters.
- **Independently verified small-task reliability exists only for Ling 3.0 Flash** (45/45 valid tool calls, 100% format adherence, but a silent empty-output bug under `max_tokens` < 2048 and first-needle bias). Mercury 2.5 has independent JSON-validity evidence. Everything else is vendor-reported.
- **Hallucination profiles differ sharply:** Solar Pro 4 abstains (24% hallucination, 41% attempt rate), Ling Flash 44%, Muse Glimmer 82%, Inkling Small has a negative Omniscience score. For Memory-extractor/Summarizer roles, Solar Pro 4 and Mercury 2.5 (compaction case) are the safest; Glimmer and Inkling Small need grounding checks.
- **Latency:** Muse Glimmer has the best TTFT (1.03 s) and moderate throughput (98 tok/s); Ling Flash is the throughput leader among AR models (345–368 tok/s, TTFT ~2–2.5 s); Mercury 2.5 wins only for long outputs, since its TTFT scales with output length (up to 5+ s). Solar Pro 4 is slowest (71 tok/s, 8.6 min/task). Nex Mini is unmeasured.
- **Provider/uptime risk:** Nex Mini's sole free endpoint showed 79% daily uptime; Together's Glimmer endpoint 95%; Solar Pro 4 and Mercury 2.5 are single-vendor; Ling Flash context differs 2x between Novita and DeepInfra; Inkling Small serves 524K vs the 1M card on two of three providers.
- **Role mapping (safe delegations):** Summarizer/compaction → Mercury 2.5 (reasoning off) or Solar Pro 4 (long docs). Memory-extractor with JSON schema → Ling Flash (`max_tokens` ≥ 2048, explicit dates) or Solar Pro 4. Investigator (tool-heavy grep/read loops) → Muse Glimmer (if ATEM parsing verified) or Ling Flash. Editor for small verified diffs → Inkling Small (paid) or Muse Glimmer. Reviewer → Solar Pro 4 for docs; none of these for blocking code-review gates (Ling had 73% false positives). Visual-verification sub-tasks → Nex Mini (experimental) or Ling VL. Planner → none of this tier.
- **Open-weight local feasibility:** Only Muse Glimmer fits 24–32 GB GPUs (17–20 GB 4-bit). Nex Mini needs ~21 GB Q4 GGUF plus 32 GB RAM. Ling Flash/VL need ~70 GB at 4-bit (2 GPUs on the vendor int4 path). Inkling Small needs 88 GB even at 2-bit.


### Cross-tier synthesis for the VCP multi-model strategy

This section translates the evidence above into inputs for §7 of vcp-what.md. Everything here is a proposal to be validated in P6-04; nothing is a measured VCP result.

#### 1. What the evidence says about routing in general

- **Cost per solved task diverges from list price by up to 25x.** Qwen3.8 Max ($2/$6) costs $5.41 per AA task; GPT-6 Astra ($10/$50) costs $3.26. Muse Spark 1.3 at $1.25/$4.25 solves agent tasks for $0.55, GPT-5.6 Luna for $0.20, DeepSeek V4.1 Flash for ~$0.25. The router's "estimated total cost" step (§7.5 step 3) must use measured tokens-per-task by task class, not price × nominal context. The budget ledger (§8) already tracks this; the routing evaluation (E19) should feed it back.
- **Verbosity is the dominant cost driver and is controllable.** AA flags nearly every non-Anthropic model as "very verbose" at default effort, and several hands-on reports show default `xhigh`/`max` effort causing overthinking loops (Qwen3.8 27B: 22K reasoning tokens for an SVG circle; Sol: high effort "made it dumber"; DeepSeek V4.1 Flash: "re-arguing a point already answered"). VCP should set per-role effort and `max_tokens` caps in the catalog and verify the effort parameter actually reaches the provider (two DeepSeek integrations silently dropped it).
- **Vendor harness numbers do not transfer.** Terminal-Bench 2.1 drops 8–19 points from vendor to Vals for every High-tier model and 33 points for DeepSeek V4 Pro. DeepSWE varies by harness for the same model. This supports §7.2's rule that the OpenRouter catalog is a filter input, not evidence, and §21.9's rule to keep a fixed model for any task class where routing underperforms.
- **Long-horizon capability is where tiers actually separate.** On Terminal-Bench 4.0 the Frontier tier scores 52–59% (Astra, Fable 5.1, Opus 5), Sol 37–40%, and every High/Medium model 11–31%. Terminal-Bench 2.1 and DeepSWE are near-saturated and no longer discriminate. Escalation triggers (§7.5 step 7) should key on task length and tool-turn count, not just failed tests.
- **No model is a safe standalone Reviewer.** Opus 5 (55% recall), Sol (32% precision), Terra (36% precision), Luna (74% precision), Astra (noise), GLM Flash/Ling (high false positives). Review should use two models with different failure profiles, or one model plus verification tooling. This aligns with §7.4's "selective independent review" and argues against a single Reviewer role default.
- **Provider variance on OpenRouter is a first-order variable.** Same-weight quality swings of 15 points (GPQA) and 20 points (tool calling) across DeepSeek V4 Flash providers; GLM 5.3 Flash thinking loops on NVIDIA NIM but not on Z.ai; 4–7x throughput spreads; context served at half the card on some Inkling Small and Ling endpoints. The catalog's Identity/Exceptions fields need provider-level rows, and P2-02 conformance tests should run per provider, not per model.
