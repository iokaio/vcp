Implement the E-A workload while preserving the original TaskBoard API/UI and protected tests.

- `GET /api/tasks/export` returns HTTP 200 `{ "schemaVersion": 1, "tasks": [...] }`, every stored task field unchanged, tasks sorted by ordinal string ID. Empty storage exports an empty array.
- `POST /api/tasks/import` accepts that document. Validate the entire document before writing. Preserve supplied IDs and all fields, including timestamps, labels and null due dates. Identical existing records are unchanged; new IDs are appended; any differing existing record rejects the whole document with HTTP 409 `IMPORT_CONFLICT`. Repeating an identical or empty import returns 200 without mutations. A successful first import may return 200 or 201.
- Unsupported/missing schema version, duplicate IDs and any invalid task reject the entire document with HTTP 400 `VALIDATION_ERROR`. Use the original nested error shape. Retain original field validation, including real calendar dates. Atomically persist the merged state; never partially import a rejected document.
- The existing UI gains a keyboard reachable button with accessible name `Export tasks` that downloads the actual export document, and a keyboard reachable file input labeled `Import tasks`. Show request progress, visible errors with `role="alert"`, and an import/unchanged summary with `role="status"`. The independent browser check actually downloads and reimports data, checks invalid input and a new record, and preserves original UI hooks.
- Add tests for full field round-trip, empty export, Unicode, atomic rollback, conflicts, repeat import and persistence. Document the format and operational behavior.
