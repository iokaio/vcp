## Why the run failed and what changed

1. **Metadata expired between tasks.** A started at 09:27 Denver time on October 3,
   2026; its endpoint snapshot expired at 09:54. At 10:07:51, `T2-ui-repair1`
   was rejected before task acceptance: `provider metadata is stale or differs
   from qualification`. Startup-only checking cannot prevent this.

   `setup provider-refresh` now fetches public endpoint metadata without a key
   or inference. It validates the captured snapshot and compiled adapter contract,
   then reparses current prices, availability and capabilities for the same exact
   model and endpoint. It neither extends the adapter contract nor silently
   converts empirical qualification. The launcher and each new task/repair
   ensure metadata covers the task deadline plus five minutes. Fresh generations
   and cloned profiles preserve the old evidence and authorization. Resumes and
   session forks retain native task-captured selections; supplying another profile
   does not replace those snapshots. An expired captured fixed snapshot still fails
   native admission; no immutable task is silently rebound.

2. **The tests changed source identity while verification ran.** All three completed
   attempts recorded passing `package.json#test` checks but stale verification.
   Retained verification-result artifacts identify exactly one changed path:
   `tests/tmp/tasks.json`. The generated tests deleted and recreated this database.
   Its final content was unchanged (383 bytes; SHA256
   `df67c5ddb66202aff38bf6a7527f625fa0a399452b4c1d3d778bd0165410a492`),
   but its Windows file identity changed. Rejecting that evidence was correct.

   Scenario instructions now require unique OS temporary directories, explicit
   database paths, awaited server shutdown and cleanup. Seeded health and protected
   regression tests use this lifecycle. Existing authored tests are not overwritten;
   the agent is instructed to repair the old pattern while preserving assertions.
   Native verification diagnostics name changed paths and distinguish source,
   task/authority and observation failures. The freshness check remains strict.

3. **UI patches did not land.** T2's change record lists only `package.json` and
   `package-lock.json`, despite its completion message claiming components and tests.
   Retained tool results show malformed Add File hunks, then missing-parent errors
   for `src/api/tasks.ts` and `src/composables/useTasks.ts`. Calling Node with `mkdir`
   as its script also failed. The independent gates correctly found only the original
   heading test and none of the six required UI test hooks.

   The scaffold now creates empty `src/api`, `src/composables` and `src/components`
   directories, including when reusing a project, and explains valid Add File syntax
   and Node directory creation. It supplies no UI implementation. Repair instructions
   include actual changed-file evidence and require readback. Repairs must exit 0;
   incomplete completion evidence is no longer accepted as a successful repair.
   The agent must still implement the features and pass the unchanged acceptance gates.

4. **A rejected command inflated reported spend.** Earlier task ledgers totaled

   A single complete unscoped configuration result, matching process exit 2, with no
   accepted frame, invalid lines, timeout or other conditions now records zero new
   spend. The execution failure remains a failure. Truncated, interrupted or ambiguous
   execution retains its conservative reservation and cannot clear earlier liability.

5. **Repeated inspection dominated runtime.** The command audit contains 51

   later commands took roughly 75 seconds each. The stopped database has 2,091 commits.

   `inspect-bundle <task>` collects the standard six views, agent records and task history

   saves both the bundle and per-view files and validates task/watermark/completeness.
   Final response bytes still use the existing hash-checked range read. Older CLIs fall
