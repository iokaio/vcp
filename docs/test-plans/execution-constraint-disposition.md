# Execution constraint evidence and test disposition

Work items: EE-01b/e, with diagnostic support for EE-00c and EE-05. This inventory describes the `feature/execution-engine-refinements` source and focused evidence on October 4, 2026. The [architecture review](../architecture/execution-architecture-review.md) defines the intended destination; the [work ledger](../plan/25-execution-engine-refinements.md) records completion. A planned suspension is not proof that every enforcement layer has changed.

The original automatic-review hold was resolved by the owner's explicit "Approved. Continue." clarification and fresh accepted reviews. CLI effective execution now uses unbounded limits with recorded original/effective policy and executable identity. Finite compatibility fixtures remain active. The harness no longer applies run/continuation wall-clock cutoffs or scenario spend ceilings; it reports cumulative observed spend, partial settlement and unknown additional cost separately. Incomplete scoped execution or inspection still fails independently of billing. Campaign policy, forced-short probes, provider pacing and missing-price admission remain unfinished; no full A/B qualification is claimed.

## Reading the inspection evidence

`inspection_bundle.effective_constraints` is a versioned, read-only projection of the same authorized canonical watermark as the rest of the bundle. It records task/steering, session/configuration, workspace/binding, authority/deletion and ledger/policy revisions. The monetary section identifies its ledger source, currency and explicit finite/unbounded cap. Known settled amounts, active reservations and unresolved reserved liability retain different names. A reservation for an uncertain request is not an observed final bill, and missing final billing remains unknown rather than zero.

Original public-start facts are included only when `retained_start_budget` proves them from retained acceptance history. Their budget and acceptance time are historical evidence, not a claim that an active owner currently enforces the same deadline or cap. Legacy genesis without a public marker and unavailable/redacted history have distinct unknown explanations. The current owner deadline, execution/source revision and retention automation are unknown when this state projection cannot prove them. Session configuration revision is not mislabeled as a Git revision. Independent authority process limits are identified separately from task deadlines.

The projection does not open runtime configuration artifacts, reconstruct a start ticket, change a ledger, apply retention, or launch work. Task-restricted access does not read a parent/root ledger outside its authorized task set. Ordinary bundle authorization, pagination and byte ceilings still apply. Source: [constraint projection](../../src/crates/vcp-cli/src/inspection_bundle/constraints.rs), integrated by [bundle collection](../../src/crates/vcp-cli/src/inspection_bundle.rs).
