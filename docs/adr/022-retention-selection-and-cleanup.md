# ADR-022 — Exact retention selection and resumable local erasure

Status: accepted for the P5-07 experimental format.

P5-07 applies a normalized typed selector against a coherent canonical cut. A preview contains exact selected and dependent IDs, the source commitment, authority/deletion revisions, protection categories, estimated retained bytes, and known snapshot obligations. Applying never expands an old preview to newly matching history. Saving the preview is itself a canonical operation; only these exact preview metadata records/events are omitted from its source commitment. Other source changes require a fresh preview.

Dates require an explicit resolved fixed UTC offset; timestamps require their own Z or numeric offset. Date-only values mean local midnight at that supplied offset. The stored UTC instant and inclusive/exclusive bound drive selection. Named-zone DST gaps/overlaps are not guessed. Unknown metadata remains unknown under negation. Historical source root/path metadata is recovered only from retained native manifests whose source scope, hashes and byte counts agree; it does not depend on the current workspace binding. This metadata scan is bounded to 256 manifests, eight MiB and 16,384 associations. Workspace/root IDs and canonical root-relative paths remain distinct.

Recall exclusion, presentation compaction, and irreversible purge are independent. Exclusion can be reversed without changing raw records. Compaction preserves raw history and an explicit expanded view. Neither action deletes bytes. A purge first commits exact tombstones, the new deletion epoch, recall decisions, and a durable cleanup job on the controller's dispatch ordering worker. Old context seals/generations no longer match that epoch. Active task recovery, active turns, unfinished captures, and unresolved effect/accounting obligations protect their dependency closure. Apply atomically refuses the entire preview batch if any dependency is protected, including disjoint selections; those other IDs are labelled batch-blocked rather than directly live. Narrowing the selector or reconciling the protected dependency permits a new preview. A paused task alone does not prove erasure is safe.

Copied claim/proposal/result content follows canonical provenance. Captured memory passages supply typed source/evidence IDs; context manifests supply included artifact IDs and the exact provider-request hash. Settled response captures follow their canonical attempt request. Cleanup does not search for coincidentally equal strings or silently erase unrelated workspace contexts. The qualified closure is bounded to 8,192 targets, 64 expansion passes, and eight MiB of captured context metadata (one MiB per capture). Larger retained context inventories fail explicitly before mutation; they require a future capture-side lineage index rather than an incomplete preview.

The sealed replay-base mechanism in ADR-021 removes selected payload copies from the current journal/checkpoint/SQLite state while preserving opaque original receipt commitments. Explicit typed redaction marks terminal tasks, turns, effects, verification details, events, inspections, and immutable memory records. Required outcomes, IDs, scope, source hashes and liability facts remain truthful. Ordinary writes cannot introduce redacted records.

Local cleanup enumerates recognized payload files only in retired roots from the sealed activation chain and verified private rewrite staging children. It holds root snapshot leases, artifact reader/writer leases, and Windows directory handles against reparse/rename replacement. It preserves routing and lock inodes; it does not recursively remove arbitrary directories. A process crash after any removed file resumes from the committed job and the remaining exact inventory. Unknown entries and live pins remain explicit pending obligations. Generation cleanup waits for canonical snapshot and native reader pins. No result promises erasure of already submitted provider bytes, retained cloud versions, or SSD blocks.

Notification-only is the default policy. Retained history becomes due strictly beyond thirty 24-hour days. A notice records its own state without adding new retained-history age; the default repeat interval is explicitly seven 24-hour days and is configurable. Automatic actions require an explicit saved policy, selector, action, cadence, current actor authority and policy revision. Disabling/changing a policy prevents new queued applications; existing tombstones remain canonical facts.

Saved automatic policies are evaluated at canonical owner startup after recovery, before execution. Setting a policy takes effect at the next owner start; no daemon runs while the owner is closed. Protected or unavailable applications leave durable blocked status and respect the saved cadence. Read-only inspection never runs this driver. Startup also retries up to four committed purge cleanup jobs; pinned or remaining jobs stay pending and support explicit cleanup.

Qualification must distinguish logical unavailability, current replay-base redaction, local physical cleanup, pinned old copies, and retained backup copies. Native process-exit tests cover tombstone commit, before/after activation, and partial local cleanup on both Files and SQLite. Test outcomes are recorded with the implementation evidence; this decision does not claim unrun checks passed.
