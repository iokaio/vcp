## VCP modifications

- The upstream YAML front matter is not retained; `skill.json` is the only package metadata, and its description drives discovery.
- SKILL.md and references/browser-patterns.md port the static/dynamic testing decision, rendered reconnaissance, selector discovery, actions, screenshots, console diagnostics and owned-browser cleanup.
- scripts/check-page.cjs translates the upstream Python Playwright discovery and console examples to Node and the project-installed Playwright module. VCP adds locator/state waits, one button action with an exact text assertion, bounded diagnostic output, explicit screenshot output and finally cleanup.
- The helper opens a new context with Chromium sandboxing enabled, blocks service workers, sockets, off-origin requests and all redirects, and never installs dependencies, starts a server or reuses a signed-in browser profile. Request routing is a test guard, not a substitute for host network/process enforcement.
- Blanket networkidle and fixed sleeps are replaced by observable application waits. The upstream shell=True server wrapper was inspected and intentionally not copied; project/VCP process ownership remains authoritative.
- SU-09 (2026-09-29): accepts `localhost` as a loopback host; adds opt-in `--ignore-https-errors` honored only for loopback origins; asserts expected text through the same Playwright locator that was waited on, so Playwright-only selectors work; exposes `--timeout`; adds `--aria-snapshot` using Playwright's built-in `ariaSnapshot()` with exclusive-create output; adds an optional `--axe` scan that uses only a project-resolved `axe-core` (never bundled or installed), reports `unavailable` when absent and returns bounded violation ids, impacts and counts. references/browser-patterns.md adds project-test guidance for `page.route`/`route.fulfill` mocking, `storageState` authentication reuse and `context.tracing`; these are not helper features.
- SH-10 (2026-09-29): the CLI prints only the first line of an error, at most 300 characters, because Playwright call logs can include element HTML or page text. A blocked request, redirect, socket or navigation failure names up to five blocked origins (scheme, host and port only) in its message and up to ten in `error.blockedOrigins`; the docs state that any blocked request, such as a CDN font, fails the check. `--screenshot` and `--aria-snapshot` outputs must resolve under the current project root (`runCheck` option `outputRoot`): absolute paths outside it, `..` escapes, parent links resolving outside it, existing entries including links and, on Windows, stream or reserved device names are rejected before launch and re-checked before the exclusive-create write. Reference commands use the materialized copy run from the project root. SKILL.md now states that button labels, which are page text, are always returned. LICENSE.txt gained a final newline, so its descriptor hash no longer equals the upstream source hash above; the license text is unchanged. Tests cover `--help`/argument errors, missing and project-resolved Playwright, first-line truncation, output containment, page-error failure, service-worker blocking and blocked-origin reporting.
- Removes historical CS-3 receipt/qualification prerequisites for ordinary skill development while preserving authorization, package integrity and accurate statements of what was run.

## Validation scope

The adapted helper has been exercised against synthetic local HTML with an existing Playwright 1.63.0 and Chromium 153.0.8010.12 on Windows (earlier evidence used Playwright 1.61.1 and Chromium 149). The checks cover a self-signed HTTPS `localhost` server generated at test time, Playwright-only selectors, ARIA snapshot output and axe reporting. The axe checks use an absent `axe-core` and a stand-in axe object; the real axe-core rule engine was not exercised because it is not a VCP dependency. This demonstrates the helper's tested Playwright workflow, not qualification of a VCP native browser adapter. An earlier run found that a restricted host token closed Chromium before page creation; those checks passed outside that host sandbox with Chromium's own sandbox still enabled. No dependencies or browsers were downloaded. Use the available project/host permissions and report missing execution prerequisites.
