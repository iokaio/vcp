# P5-08 deterministic memory comparison

Run `pwsh scripts/evals/memory-comparison.ps1` from a provisioned Rust/native build environment. Build inputs must already be cached: the runner uses locked offline Cargo. On Windows use the repository's native toolchain setup first. Each invocation creates a fresh artifact directory; its manifest retains failures, command logs, source/toolchain/hardware identity and the report digest. Keep complete run output outside version control.

The runner hashes every file in VCP's local crates, the underlying Munarium crates, fixtures, graders and evaluation scripts, plus workspace manifests, lockfiles, toolchain and applicable Cargo configuration. It records bounded tracked-diff and untracked-content hashes with the commit before and after execution, and fails if source content or commit changes during the run. This avoids treating a dirty-tree boolean as reproducible source identity. Node is required for this source-identity capture.

`history.json` is the synthetic observation stream. `questions.json` separately freezes questions, query terms, authorized task sets, applicable relevant sources and stale sources. Ingestion never reads questions. Do not tune sources or query terms after observing scores; a changed fixture requires a new revision and recorded rerun. File hashes, grader hash and harness hash identify the exact experiment, including dirty source trees.

The example replays all history through production engine commands and canonical preference ingestion on Files and SQLite, including an explicit correction of an accepted lineage. It publishes a lexical generation before the last observation, queries it after that observation, then builds a current generation and repeats. Each mode runs every case against:

- No semantic memory: empty retained recall, with honest abstention.
- Versioned Markdown: all observation revisions retained as Markdown; deterministic lexical matching uses the frozen history's current-head and authorized-task metadata. This is a transparent reference implementation, not a model or Git benchmark.
- Governed memory: production `retrieval::query`, real canonical evidence, lexical publication and production scope/current-evidence enforcement. The report retains canonical/index watermarks, degradation codes, source identities, evidence IDs and rank components.

All strategies receive the same held-out query, authorized scope, eight-result cap and 16 KiB passage cap. Governed retrieval also counts serialized citation overhead within this cap, which is reported explicitly; the baseline bounds raw passage text. This small corpus fits both bounds. Each run starts from empty isolated state. No strategy has a model, provider or embedding call. Extraction and maintenance model spend are exactly zero. Timings and retained bytes are measured independently of task grades. Missing RSS, inference and restore-readiness measurements are null, never inferred as zero.

The reusable grader counts independent relevant labels, exact sourced hits, stale results, forbidden results, unsupported evidence and complete evidence-task outcomes. Empty output fails questions requiring recall and passes appropriately unsupported/unauthorized questions. Every attempted case remains in the report, including errors; failed attempts stay in denominators. A governed failure causes a nonzero exit after saving the report. Setup/build failures remain in the outer run manifest and are never presented as query success. The unit test verifies duplicate citations cannot inflate recall and stale, restricted, unsupported or failed attempts cannot pass.

This qualifies deterministic sourced-evidence tasks over explicit preferences. It does not establish model answer quality, semantic vector recall, broad natural-language extraction, restore correctness or the full P5-08 gate; those require the separate subsystem and fault campaigns. A perfect score on six synthetic cases is not a general memory-quality claim.
